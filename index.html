无障碍网页设计示范

本页面以欧洲无障碍法案（EAA）等国际标准为指导，既讲解无障碍的关键要求，又以自身实现作为示范。

  • 检查清单

语义结构与层次

语义化 HTML 能帮助屏幕阅读器正确理解页面层级，也是遵循 EAA 与 WCAG 的基础。本示例使用 <header>、<main>、<nav>、<section> 与 <footer> 等元素来体现结构。

  • 标题使用按层级递进的 <h1>~<h3>。
  • 导航区添加 aria-label 以说明用途。
  • 主要内容区使用 tabindex="-1"，配合跳转链接支持键盘快速定位。

文本替代内容

图像、图标等非文本内容需要提供清晰、简洁的替代文本。下方示例图片使用 alt 属性描述其含义，而非简单重复文件名。

预览

代码示例

<figure>
  <img src="inclusive-design.png"
       alt="一个象征包容性设计的插画：多样化人群围绕电脑讨论。">
  <figcaption>图片说明提供了额外上下文。</figcaption>
</figure>

实现要点：

  • 对纯装饰性图片可设置 alt=""，并通过 CSS 背景或 role="presentation" 标记。
  • 为图表提供文字数据概述或链接到完整数据表。

颜色对比

文本与背景的对比度需要满足 WCAG 2.1 AA 标准：普通文本至少 4.5:1，大字号文本至少 3:1。示例对比如下：

预览

合格的对比度

深色背景搭配亮黄色文字，符合 7:1 以上的对比度要求。

不合格的对比度

浅蓝背景配浅色文字，对比度不足，低视力用户难以阅读。

代码示例

/* 高对比度示例 */
.contrast-good {
  background: #102840;
  color: #ffcc33; /* 对比度 > 7:1 */
}

/* 低对比度示例（请避免） */
.contrast-bad {
  background: #eef2ff;
  color: #b0c4ff; /* 对比度 < 3:1 */
}

设计时可使用 Contrast Checker 或浏览器开发者工具进行验证。

键盘操作与焦点管理

确保所有交互元素都可通过键盘访问，焦点状态清晰可见。本页提供顶部“跳到主要内容”链接，并通过 :focus 样式突出焦点。

  • 焦点顺序应与视觉顺序一致。
  • 避免在焦点进入时触发突然的内容变化。
  • 必要时通过 tabindex 控制顺序，但尽量使用默认流。

介绍 指南 资源

使用 Tab 键可依序访问链接，并在按下跳转链接后把焦点带到这里。

代码示例

<a class="skip-link" href="#content">跳到主要内容</a>

<nav aria-label="主导航">
  <a href="#intro">介绍</a>
  <a href="#guides">指南</a>
  <a href="#resources">资源</a>
</nav>

<main id="content" tabindex="-1">
  <p>当跳过导航时，焦点会落在这里。</p>
</main>

.skip-link {
  position: absolute;
  top: -40px;
  left: 1rem;
}

.skip-link:focus {
  top: 1rem; /* 焦点时可见 */
}

无障碍表单

表单控件需要配对的 <label>，并提供清晰的错误反馈。以下示例演示无障碍反馈方式：

预览

所有字段均可通过键盘访问，提交按钮在键盘操作下同样可用。

代码示例

<form aria-describedby="form-hint">
  <p id="form-hint">所有字段均可通过键盘访问。</p>

  <label for="name">姓名</label>
  <input id="name" name="name" type="text"
         required aria-required="true">

  <label for="email">电子邮箱</label>
  <input id="email" name="email" type="email"
         required aria-required="true">

  <label for="feedback">想了解的无障碍主题</label>
  <textarea id="feedback" rows="4"></textarea>

  <label for="assistive-tech">常用辅助技术</label>
  <select id="assistive-tech">…</select>

  <button type="submit">提交示例</button>
</form>

常见实践：

  • 在错误提示上使用 aria-live="polite"，确保屏幕阅读器可感知。
  • 为必填项添加 required 与 aria-required 双重声明。
  • 使用清晰的占位符与说明文本，避免依赖颜色区分状态。

合理使用 ARIA 与辅助技术支持

ARIA 用于补充原生语义，而非替代。以下是本页应用的示例：

  • 导航菜单使用 aria-label 描述用途。
  • 颜色对比示例容器使用 role="group" 与 aria-label 提供额外上下文。
  • 表单使用 aria-describedby 将提示文本与表单关联。

预览

原则 模式 测试
✅ 设置已保存，将通过屏幕阅读器播报。

按钮会在保存后更新上方状态区域。

原则部分：介绍如何选择合适的语义标签。

模式部分：提示组合组件时先采用原生元素。

测试部分：建议使用多种辅助技术验证。

代码示例

<div aria-label="ARIA 属性示例">
  <nav aria-label="辅助功能文章导航">
    <a href="#principle">原则</a>
    <a href="#pattern">模式</a>
    <a href="#testing">测试</a>
  </nav>

  <div role="status" aria-live="polite">
    ✅ 设置已保存，将通过屏幕阅读器播报。
  </div>

  <button type="button" aria-describedby="aria-tip">
    保存偏好设置
  </button>
  <p id="aria-tip">按钮会在保存后更新上方状态区域。</p>
  <p id="principle" class="sr-only">原则部分：介绍如何选择合适的语义标签。</p>
  <p id="pattern" class="sr-only">模式部分：提示组合组件时先采用原生元素。</p>
  <p id="testing" class="sr-only">测试部分：建议使用多种辅助技术验证。</p>
</div>

实践提示：

  • 先选择语义正确的 HTML 元素，再考虑添加 ARIA 属性。
  • 避免使用会破坏屏幕阅读器体验的 role="application" 等属性。
  • 定期使用 NVDA、VoiceOver 等辅助技术进行测试。

快速自检清单

在发布前，可依据以下清单自测是否符合 EAA 等国际标准：

  • 所有非文本内容都有恰当的替代文本。
  • 文本对比度符合 WCAG 2.1 AA 要求。
  • 提供键盘可访问的导航与焦点可视化。
  • 表单控件有明确标签与错误提示机制。
  • 动态内容通过 aria-live 或其他方式告知辅助技术。
  • 页面语义结构清晰，使用正确的标题层级。
  • 避免仅用颜色传达信息，提供文字或图标辅助。
  • 支持多语言或提供语言标记 lang 属性。
